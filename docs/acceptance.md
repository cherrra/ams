# Чек-лист приёмки

Сверка нового приложения с legacy по экранам и сценариям. Отмечайте пункты после ручной
проверки; для каждого экрана указан маршрут в новом клиенте.

## Как проходить

1. Запустить БД, API и Expo (см. `README.md`, раздел «Запуск мобильного приложения»).
2. Проверить в браузере (`http://localhost:8081`) и на телефоне в Expo Go.
3. Демо-доступы: `admin@ams.local` / `Admin12345`, `user@ams.local` / `User12345`.
4. Для проверки роли клиента удобно заранее завести отдельного пользователя через регистрацию.

## Сценарии

### Регистрация и вход
- [ ] Новый пользователь регистрируется и сразу попадает на главную.
- [ ] Повторная регистрация с тем же email даёт понятную ошибку (409).
- [ ] Неверный пароль — сообщение «Неверный email или пароль», приложение не падает.
- [ ] После перезапуска приложения сессия сохраняется (refresh-токен работает).
- [ ] «Выйти из аккаунта» очищает сессию и возвращает на экран входа.

### Каталог и запись
- [ ] Категории и услуги подгружаются, поиск фильтрует список.
- [ ] Нельзя записаться без автомобиля — приложение предлагает добавить авто.
- [ ] Занятые слоты недоступны; при гонке API отвечает 409 и показывает понятное сообщение.
- [ ] Итоговая цена складывается из выбранных услуг.
- [ ] После создания заказ виден на главной и в «Заказах».

### Заказы
- [ ] Активные и завершённые заказы разделены, статус отображается бейджем.
- [ ] Клиент может отменить активный заказ; завершённый — нельзя.
- [ ] Смена статуса админом отражается у клиента без перезагрузки (polling ≤ 30 с).
- [ ] В Expo Go при смене статуса приходит системное уведомление, на web — баннер.
- [ ] Нажатие на уведомление открывает карточку заказа.

### Гараж
- [ ] Авто добавляется, редактируется и удаляется; марка и модель создаются «на лету».
- [ ] Нельзя удалить авто, если есть активные заказы (API вернёт понятную ошибку).
- [ ] Фото авто загружается, отображается и сохраняется после перезапуска.

### Профиль
- [ ] Имя, телефон и дата рождения редактируются; телефон принимает форматы `+7...`.
- [ ] Аватар загружается и виден в шапке профиля.
- [ ] Удаление аккаунта удаляет пользователя и возвращает на экран входа.

### Админка
- [ ] Обычный пользователь не попадает в `/admin/*` (редирект на главную).
- [ ] Категория и услуга создаются, редактируются, удаляются.
- [ ] Нельзя удалить категорию/услугу, если они используются в заказах.
- [ ] Поиск по заказам и клиентам работает.
- [ ] Статус меняется только по допустимым переходам (`created → accepted → in_progress → completed → finished`).
- [ ] Админ получает уведомление о новой записи.

## Проверка API

- [ ] `powershell -ExecutionPolicy Bypass -File scripts\smoke.ps1` — все шаги зелёные.
- [ ] Swagger открывается на `http://localhost:3005/docs`.
- [ ] Healthcheck отвечает `{"status":"ok"}`.
- [ ] Ошибки валидации возвращают 400 с массивом сообщений.
- [ ] Запрос без токена — 401, с токеном клиента к админской ручке — 403.

## Производительность и устойчивость

- [ ] Список из 50+ услуг и 100+ заказов прокручивается без заметных рывков.
- [ ] При выключенном API приложение показывает ошибку и не зависает.
- [ ] После восстановления сети данные загружаются повторно (кнопка «Повторить» / возврат на экран).
- [ ] Приложение корректно работает при повороте экрана и на маленьком экране (5").
